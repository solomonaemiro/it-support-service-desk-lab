#Knowledge Base

##Overview

The osTicket Knowledge Base was configured to provide users with self service guidance for common IT Support issues.

The objective was to reduce unnecessary ticket escalation for routine problems while giving users clear, safe troubleshooting steps that can be followed without advanced technical knowledge.

The articles were written from an end user perspective, using simple instructions and avoiding unnecessary technical commands where a graphical Windows solution was sufficient.

The FAQs were organized into four support categories:

- Windows & Software
- Network & Connectivity

Each article provides simple troubleshooting steps that an end user can perform safely before escalating the issue to IT Support.

###User-Focused Writing

The FAQs were intentionally written for end users rather than support technicians.

Instructions use straightforward actions such as:

- Open Settings
- Select Windows Update
- Open Task Manager
- Restart the computer
- Check the Wi-Fi connection
- Contact IT Support if the problem continues

Advanced diagnostic commands were avoided when they were unnecessary for the intended audience.

This distinction is important in a real Service Desk environment because technical documentation should match the knowledge level of its intended audience.

---

###Consistent FAQ Structure

Each FAQ follows a consistent structure:

Question → Problem explanation → Troubleshooting steps → Escalation guidance

This approach makes the articles easier for users to follow and creates consistency across the Knowledge Base.

The articles are designed to help users perform appropriate first-level troubleshooting while identifying situations that require IT Support intervention.

---

###Relationship Between the Knowledge Base and Tickets

The Knowledge Base and ticketing system serve complementary purposes.

###Knowledge Base

Provides users with self-service instructions for common and repeatable problems.

###Service Desk Tickets

Provide a structured workflow when:

- Self-service troubleshooting does not resolve the problem.
- The issue requires technician intervention.
- The problem requires investigation or diagnosis.
- The incident needs to be documented and tracked.

This creates a simple support escalation model:

Self-Service → IT Support Ticket → Technician Troubleshooting → Resolution

---

###Knowledge Base Design Principles

The content was developed around several principles.

###1. Clear Language

Instructions use straightforward language that non-technical users can understand.

###2. Safe Troubleshooting

Users are guided toward low-risk actions before more advanced intervention is required.

###3. Step-by-Step Instructions

Each article breaks troubleshooting into manageable actions.

###4. Appropriate Escalation

Articles explain when the user should stop troubleshooting and contact IT Support.

###5. Consistency

Similar support issues follow a consistent documentation format, making the Knowledge Base easier to maintain.

---

###Knowledge Base Outcome

The completed Knowledge Base provides a foundation for self-service support while also giving technicians a consistent reference for common incidents.

It demonstrates an important Service Desk principle: not every technical problem needs to begin with a technician.

Well written self service documentation can resolve simple issues quickly, reduce repetitive tickets, and allow support staff to focus on incidents that require technical investigation.
